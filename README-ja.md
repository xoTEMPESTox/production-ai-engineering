# プロダクション AI エンジニアリング (Production AI Engineering)

### 本番環境における AI システムの設計、構築、デプロイ、運用の方法を学ぶ。

---

## 🌟 プロジェクトのビジョン

本リポジトリは、よくある単なる AI フレームワークや玩具のようなチャットボット、あるいはシンプルな RAG テンプレートの紹介プロジェクト**ではありません**。

**その真の目的は、本番環境レベルの「AI システムエンジニアリング」を体系的に学ぶことです。**

100行程度のコードで簡易的なエージェントを構築するチュートリアルは、インターネット上に無数に存在します。しかし、ネットワークの切断に耐えるリトライ設計、コンタクトを再開させる状態チェックポイント、タスクキューのバックプレッシャー管理、非同期のバックグラウンドワーカー、SQL/NoSQLでの状態永続化、本格的なコンテナデプロイ、Prometheusを用いたコストや遅延の計測、および長期間の複雑なワークフローなど、実運用に耐えうる頑健なシステムへの進化を解説する教材は極めて稀です。

**本プロジェクトはそのエンジニアリング上の大きなギャップを埋める存在です。**

すべての章は、学習しやすい最小構成のプリミティブ実装からスタートし、ステップバイステップでプロダクション要件を満たすコードへと進化していきます。最終章の統合システムでは、これまでに学んだすべての設計パターンを融合させ、実際のシステム運用経験から着想を得た包括的な AI プラットフォームを動かします。

## 🎯 対象読者
* **バックエンドエンジニア**：AI システムを支える頑健でスケーラブルなインフラ構築に関心がある方。
* **AI & 大規模言語モデル (LLM) エンジニア**：プロトタイプ開発や単純なプロンプトの連結から一歩進み、本番運用可能なレジリエントなエージェントを設計したい方。
* **コンピュータサイエンスを学ぶ学生**：基盤モデルの時代において、現代のソフトウェアエンジニアリングが実務でどのように適用されるか理解したい方。

## 🧠 設計思想：フレームワークに依存しないエンジニアリング

特定のサードパーティ製ライブラリ（LangChain や LangGraph など）の利用方法を教えるのではなく、その下層にある**本質的なエンジニアリング原則**に焦点を当てています。そのため、学習する設計思想やアーキテクチャパターンは、どのようなオーケストレーションフレームワークや LLM API を選択する場合でも共通して役立ちます。

各章では、常に以下の問いへの答えを掘り下げます：
> *「この機能は、実運用の高負荷環境において、どのように実装され、どのように安定稼働させるべきか？」*

* **簡潔さよりも読みやすさ**：コード量を減らすための省略は行いません。すべてのコードは、本番環境の設計基準（厳密な型定義、クリーンアーキテクチャ、関心の分離など）に従って記述されます。
* **完全なオリジナルと自律性**：コピーされたプロンプトや、クローズドなビジネスロジック、あるいは特定のプロプライエタリ製品への依存は一切ありません。

```
production-ai-engineering/
├── part-1-foundations/             # フェーズ 1：コアの基礎とプリミティブ (f01–f15)
│   ├── 01-state/                   # スレッドセーフ、コピーオンライト、バージョン管理された状態ストア
│   ├── 02-agent-loop/              # モデルに依存しない自律実行制御ループ
│   └── ...                         # 構造化出力、メモリ、HITL、タイミングスケジュール
│
├── part-2-production-patterns/     # フェーズ 2：本番運用の設計パターン (p16–p30)
│   ├── 16-retry-patterns/          # エラー分類に基づく指数バックオフと再試行ジッター

│   ├── healthcare-platform/        # 医療総合連携プラットフォーム（HIPAA準拠を意識した設計）
│   └── ...                         # 顧客対応システム、学術文献調査アシスタント、サンドボックス型開発 Agent
│
├── part-4-infrastructure/          # フェーズ 4：ローカルコンテナインフラ構成 (i01)
│   └── local-compose-deployment/   # Docker Compose 統合マルチコンテナ環境仕様
│
├── common/                         # 共通ユーティリティヘルパーライブラリ
└── web/                            # Next.jsで構築されたインタラクティブビジュアライザ・ドキュメントサイト
```

基礎とパターンの各章には必ず以下の要素が含まれます：
1. **README.md**：コンセプト解説、簡易実装との比較、本番向け進化アプローチ、および設計上の決定とトレードオフ。
2. **architecture.md**：ASCIIアートで描かれたコントロールフローとモジュール連携の設計図。
3. **example.py**：本番稼働基準を満たす、型定義付きの runnable な Python 実装。
4. **tests.py**：多重スレッドや例外などの境界状況における安定稼働を検証する自動テスト。

## ⚡ 開発者向けビジュアライザ UI

本プロジェクトには、エージェントのタスク進行図、コード差分、および実行トレースを直感的に確認できる Next.js ドキュメント大盤が用意されています。

### ローカルでの起動手順

1. **Python ライブラリのインストール**：
   ```bash
   pip install -r requirements.txt
   ```

2. **Next.js フロントエンドアプリの起動**：
   ```bash
   cd web
   npm install
   npm run dev
   ```
   ブラウザで [http://localhost:3000](http://localhost:3000) を開くと、インタラクティブドキュメントを体験できます。

3. **データの再抽出**：
   レッスンコードやドキュメントを変更した際は、以下のコマンドを実行し、静的データインデックスを更新します：
   ```bash
   npm run extract
   ```

## 🚀 未来の拡張性と動作モード

本ドキュメントサイトは、以下の2つのモードで動作するように設計されています。

### 1. スタティック読込モード (Learning Mode)
* **GitHub Pages** 上で完全に静的に動作し、即座に閲覧可能。
* ローカルバックエンドサーバーや Docker を立ち上げる必要はありません。
* ブラウザ上で設計ドキュメントの閲覧、Pythonコードの読込、およびシミュレートが可能です。

### 2. ローカルインタラクティブモード (Interactive Mode)
レッスンディレクトリでインフラコンテナを起動します：
```bash
docker compose up
```
サイトはバックエンドの健康チェック用API（`/health`）を自動的にポーリングし、通信が成功すると、元のドキュメントページが**ライブ動作可能な実験環境**に変化します：

* **エージェント実行のリアルタイム追跡**：任意の文字を入力し、ブラウザ上でエージェントがタスクを解決する過程をモニタリングできます。
* **キューと処理状況の監視**：メッセージキューに溜まるタスクと消費者の負荷分散状況を視覚的に追跡します。
* **リトライとジッター監視**：通信エラー発生時に、バックオフタイマーがカウントダウンされリトライされる様子を監視できます。
* **OpenTelemetryによる遅延追跡**：どのステップで遅延が発生し、どれだけのトークン費用が消費されたかを記録します。

#### ライブデモの起動
レッスン閲覧時、画面に **🚀 Launch Live Demo** ボタンが表示されます。バックエンドが起動していない場合は、以下の説明が表示されます：
> *「`part-3-complete-systems/healthcare-platform/` ディレクトリで `docker compose up` を実行し、ページをリロードしてください。」*

接続が完了すると、ドキュメントがリアルタイムな運用テスト環境へと姿を変えます。
